# Toolkit electronics

Electronics tooling for OpenDAP: the PCB and schematic craft checks, the layer stack and impedance solver, and board variants.

## Tools

Reached through `odw <tool>` (`odapkit <tool>` is its alias), from `bin/`, and declared in `tools.toml`. `bin/` holds thin entry points only. Every tool follows the [command standard](../core/docs/specs/command-standard.md): an unknown flag exits 2; errors carry a stable dotted code, a hint and a fix, from the [shared helpers](../core/docs/specs/cli-conformance.md#shared-helper) (core's `clihost.py`, `lib/cli.sh`); `--json` documents carry a `schema`.

- `odw craft check [--json] [--target Qn] [--no-drc] BOARD.kicad_pcb` — checks a board against the parts of kicad-lib's [PCB craft standard](https://github.com/opendap-project/libs/blob/main/kicad/docs/specs/pcb-craft-standard.md) that DRC cannot check (reference designators, pin-1 marks, markings, placement grid and groups, mirrored channels, drill and via sets, zones, documentation layers), folds in the board's DRC rules tagged `[Qn]`, and reports the results by quality level (RFC 0010) with the level the board reaches. Runs [`pcb/craft/pcb-craft-check.py`](pcb/craft/pcb-craft-check.py) with KiCad's Python; configuration in `<project>.craft.toml`.
- `odw craft check [--json] [--target Qn] [--no-erc] ROOT.kicad_sch` and `odw craft check LIBRARY.kicad_sym` — the schematic and symbol part of the standard (§9): title block and drawing sheet, one sheet per feature block and its interface, symbol rules (KLC), fields, net names and label kinds, net classes against `netclasses.toml`, grid, junctions, text and tables; folds in the project's ERC and reports by level. Runs [`schematic/craft/sch-craft-check.py`](schematic/craft/sch-craft-check.py) with python3 and kicad-cli; configuration in the `[schematic]` table of `<project>.craft.toml`.
- `odw craft rules render SPEC.md [--check]` — the craft rules are data: [`craft/rules.toml`](craft/rules.toml) (schema [`opendap.craft-rules/v1`](schemas/craft-rules.schema.json)) holds every CRAFT rule with its section, level, rule, value, reason, source and enforcement exactly as the standard states them, plus the limits the checks read (`[rule.limits]`, each value stated in its rule's row). Both craft checks take their levels and limits from it. `render` writes the standard's rule tables from it between their `<!-- >>> odapkit craft rules §<section>: … -->` and `<!-- <<< odapkit craft rules -->` markers; `--check` reports a stale table and exits 1. `craft/tests/fixtures/craft-rules/pcb-craft-standard.md` is the standard with its tables marked.
- `odw stackup stack|design|check|validate|coupling|explore|pdn` — a board's layer stack and the trace geometry of its impedance classes from `hardware/stackup/stackup-<version>.toml`: a 2D quasi-static field solver (scikit-fem, pinned and hash-locked in `hardware/tools/uv.lock` until the one Python workspace, run through uv) with tolerance corners and a validation against closed forms; the zoned layer-count exploration with variant matrices, broadside and edge coupling, and a lumped PDN model for the plane pairing ([method](pcb/stackup/docs/stackup-method.md)).
- `odw variant list|get|diff|bom|apply|check` — a board's variants (RFC 0011) from schematic to PCB: each variant file (`opendap.board-variant/v1`) validated against its block catalog (`blocks/*.toml` records, or the Markdown catalog of RFC 0011), resolved part by part from the schematic (KiCad 10 variant data, or `Alt.<selector>.<Field>` field sets), its BOM, block- and BOM-level diffs, and `apply`: a separate output tree with the variant's KiCad data written into a copy of the project, plots, placement, the BOM checked against `kicad-cli --variant`, a variant ERC and DRC against the base, the absent-state check (every net a `dnp` block touches has a declared absent state; floating and single-pin nets reported), the software outputs (a capabilities fragment for the device description and a devicetree overlay fragment, `status` per block node), and a manifest of input and output hashes; `check` runs the absent-state check on every variant and builds each twice and compares them ([spec](docs/specs/variant-tool.md)). Python standard library and kicad-cli.
- `odw dru compose|check`, which composes a board's `<project>.kicad_dru` from its `<project>.dru.toml`, is in [`hooks/`](../hooks), next to its engine, the `kicad-dru-composed` hook, until the hook paths move (HL-71 phase 3).

Tests: from each engine's folder, `python3 -m unittest discover tests` (`test_variant.py` runs its KiCad classes on `variant/tests/fixtures/variant/board/`, a three-block KiCad 10 project with an interface table, written by `variant/tests/fixtures/variant/make_fixture.py` (run with KiCad's Python), and skips them without kicad-cli; the others need uv (also for `odw stackup`), KiCad 10). The craft-check fixtures are generated by `pcb/craft/tests/fixtures/make_fixture.py` (run with KiCad's Python); the schematic fixtures are a copy of kicad-lib's `examples/load-switch` (`schematic/craft/tests/fixtures/good/`) and its broken copy written by `schematic/craft/tests/fixtures/make_fixture.py`. `test_sexpr_model.py` covers the one S-expression model both craft checks read (`core/kicad/sexpr.py`: the parser, one form out of a large file, child lookups, and the configuration loader), without KiCad. `test_craft_rules.py` checks the rules data against its schema (through uv), that the marked standard renders unchanged and is byte-identical to the standard without its markers, that every limit is stated in its rule's row, and that the checks' limits and levels equal the data; pre-commit runs it and `odw craft rules render --check`.

## Layout

- `bin/` — the `odw-*` tools (each `odapkit-*` a link to its tool for one minor release)
- `schemas/` — the craft rules, block, variant, absent-state, capabilities and devicetree schemas (MPL-2.0)
- `pcb/fab-package.sh` — fab package from a KiCad project (runs ERC/DRC through [toolkit-hooks](../hooks), found as `$ODAP_TOOLS_DIR/hooks`, else `$ODAP_TOOLKIT_HOOKS_DIR` (deprecated), else the sibling `../hooks`); `--check` runs only the checks and writes nothing, `--json` prints `opendap.fab-package/v1`
- `pcb/craft/pcb-craft-check.py`, `schematic/craft/sch-craft-check.py` — the board and the schematic craft checks behind `odw craft`: their command lines, the limits they read from the rules data and each check's ID and level
- `craft/` — the craft rules as data (`rules.toml`) and their loader and table renderer (`craftrules.py`); `pcb/craft/` — the board model and report (`pcbmodel.py`, `pcbreport.py`: DRC fold, report; `pin1.py`: CRAFT-13's geometry); `schematic/craft/` — the schematic model, design checks and report (`schmodel.py`, `schdesign.py`, `schreport.py`: ERC fold, report); both read core's KiCad S-expression model (`core/kicad/sexpr.py`). Each takes the check script's limits through `bind()`
- `pcb/stackup/` — `odw stackup`: the command line and its reports (`stackup.py`), the stack model and its cross-sections (`stackmodel.py`), design, check, validation and coupling (`stackcheck.py`), the field solver (`fieldsolver.py`, closed forms in `analytic.py`), the layer-count exploration (`explore.py`, its zones and dielectrics in `explorezones.py`) and the PDN model (`pdn.py`)
- `variant/` — `odw variant`: the command line and its reports (`cli.py`), the block catalog readers (`catalog.py`), variant files and their validation (`variantfile.py`), part resolution, BOM and diffs (`resolve.py`), kicad-cli, the XML netlist, interface tables and KiCad variant data in S-expressions (`kicad.py`), the absent-state check (`absent.py`), the capabilities and devicetree outputs (`software.py`) and the variant build (`build.py`)
- `lib/cli.sh` — finds the shared command-line helpers for the shell tools (the Python tools load them through core's `clihost.py`): `core/` of the same repository when this checkout is one of its folders (the merged `tools` root), else `$ODAP_TOOLS_DIR/core` (`odw` exports `ODAP_TOOLS_DIR`), else `ODAP_TOOLKIT_HOST_DIR` (deprecated until HL-71 phase 4; its sibling `core/` when it names `host/` of a tools root), else the `toolkit-host` row of `repos.tsv` (`tests/test_host_lookup.py` builds both layouts)
- `tools.toml` — the tools this folder declares to the maintainers' umbrella command
- `tests/` — `test_cli_contract.py` checks every tool's command line without KiCad, ngspice or the network, and pre-commit runs it; each engine keeps its own tests beside it
- `docs/specs/variant-tool.md`, `pcb/stackup/docs/stackup-method.md` — the variant tool and the stackup method
